# tree-sitter-vcl (tico's fork)

A tree-sitter grammar for VCL, the Varnish Configuration Language, covering
both Varnish's VCL and the Fastly dialect. Forked from
[ntsk/tree-sitter-vcl](https://github.com/ntsk/tree-sitter-vcl) v0.4.1
(MIT, copyright ntsk; see `LICENSE`), which parses Varnish VCL only.

It's vendored here rather than pulled from crates.io because the Fastly
dialect diverged from Varnish 2.1 and has a long list of constructs that
the upstream grammar has no rule for. Each Fastly addition is marked
"Fastly" in `grammar.js`:

- top-level `table` (with optional type), `director` (with `.quorum = 20%`
  and nested `{ .backend = ...; }` entries), `penaltybox`, `ratecounter`
  and `pragma` declarations, and a return type on `sub NAME TYPE { }`
- statements: `declare local`, `error`, `synthetic` / `synthetic.base64`,
  `log`, `add`, `remove`, `restart`, `esi`, `goto` and `LABEL:`, and
  `include` inside a subroutine
- `set` with the compound assignment operators (`+=`, `-=`, `*=`, `/=`,
  `%=`, `|=`, `&=`, `^=`, `<<=`, `>>=`, `rol=`, `ror=`, `&&=`, `||=`)
- expressions: string concatenation by juxtaposition
  (`"a " req.url " b"`), the `if(cond, a, b)` function, parenthesized
  sub-expressions, header subfields (`req.http.Cookie:name`), float and
  negative literals, and `return EXPR;` from typed subroutines
- Varnish's inline C, `C{ ... }C`, at top level or in a subroutine, as a
  single `inline_c` token (upstream has no rule for it either); tico
  re-highlights the body with its C grammar

Two upstream shapes changed along the way: `return (action)` now parses
as a `parenthesized_expression` around the action (so that `return`
can also take a plain expression), and backend/probe property values are
full expressions (so a probe's `.request = "a" "b" "c"` concatenates).
The grammar also declares `word: identifier`, so keywords are only
recognized where the grammar allows them and `set req.http.set = ...` is
fine.

## Files

- `grammar.js` — the grammar; the only file to edit by hand
- `src/parser.c`, `src/grammar.json`, `src/node-types.json`,
  `src/tree_sitter/*.h` — generated by `tree-sitter generate`, ABI 15
- `LICENSE` — upstream's MIT license
- `tree-sitter.json` — upstream's grammar metadata, kept for the CLI

tico's `build.rs` compiles `src/parser.c` directly with the `cc` crate,
and `src/syntax/languages.rs` declares the `tree_sitter_vcl` entry point.
The highlight query lives with the others in `src/syntax/queries/vcl.scm`.

## Regenerating

After editing `grammar.js`, regenerate the parser with the tree-sitter
CLI (0.25 or newer) and a JavaScript runtime it can find (`node` by
default), then run tico's tests:

```sh
cd grammars/tree-sitter-vcl
tree-sitter generate
cd ../..
cargo test syntax
```

`tree-sitter parse FILE.vcl` from the same directory prints the tree for a
sample file, which is the quickest way to check a new construct; the
`syntax::tests::vcl_fastly_dialect_parses_and_highlights` test keeps a
Fastly sample that must parse without a single `ERROR` node.
